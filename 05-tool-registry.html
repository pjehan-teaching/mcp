Organiser les tools

Un contrôleur qui grossit

Chaque nouveau tool ajoute à McpController :

  • une méthode qui le décrit (listTicketsTool())
  • une méthode qui l'exécute (listTickets())
  • un cas de plus dans tools/list, tools/call et la vérification du nom
  • les dépendances de chaque tool dans le constructeur

Avec dix tools, le contrôleur mélange le transport (en-têtes, version, JSON-RPC) et le métier (les tickets).

Une classe, une responsabilité : le contrôleur gère le protocole, chaque tool devient un service.

Le plan

src/
├── Controller/
│   └── McpController.php        protocole : en-têtes, version, JSON-RPC
└── Mcp/
    ├── McpToolInterface.php     contrat commun à tous les tools
    ├── McpToolRegistry.php      collecte les tools, les liste et les appelle
    └── Tool/
        ├── ListTicketsTool.php  un tool = une classe
        └── GetTicketTool.php
  1. Un contrat : une interface que tout tool implémente
  2. Un registre qui reçoit automatiquement tous les tools
  3. Un contrôleur qui délègue au registre

Un contrat commun

<?php

namespace App\Mcp;

use Symfony\Component\DependencyInjection\Attribute\AutoconfigureTag;

#[AutoconfigureTag('app.mcp_tool')]
interface McpToolInterface
{
    /** Définition envoyée par tools/list : name, description, inputSchema */
    public function definition(): array;

    /** Résultat renvoyé par tools/call : content (+ isError) */
    public function call(array $arguments): array;
}

Les deux méthodes reprennent exactement les deux méthodes privées du contrôleur.

#[AutoconfigureTag]

Posé sur une interface, l'attribut ajoute un tag à tout service qui l'implémente.

  • Les classes de src/ sont des services autoconfigurés par défaut (config/services.yaml)
  • Créer une classe qui implémente McpToolInterface suffit : aucune configuration à écrire
  • Un tag est une étiquette qui permet de retrouver un groupe de services
php bin/console debug:container --tag=app.mcp_tool
  Service ID                     Class name
  App\Mcp\Tool\GetTicketTool     App\Mcp\Tool\GetTicketTool
  App\Mcp\Tool\ListTicketsTool   App\Mcp\Tool\ListTicketsTool

Un tool = une classe

<?php

namespace App\Mcp\Tool;

use App\Mcp\McpToolInterface;
use App\Repository\TicketRepository;
use Symfony\Component\Serializer\SerializerInterface;

final class ListTicketsTool implements McpToolInterface
{
    public function __construct(
        private readonly TicketRepository $tickets,
        private readonly SerializerInterface $serializer,
    ) {
    }

    public function definition(): array
    {
        return [
            'name' => 'list_tickets',
            'description' => 'Liste les tickets de support, éventuellement filtrés par statut.',
            'inputSchema' => [
                'type' => 'object',
                'properties' => [
                    'status' => ['type' => 'string', 'enum' => ['open', 'closed']],
                ],
            ],
        ];
    }

Chaque tool déclare ses propres dépendances : le contrôleur n'a plus besoin du dépôt ni du Serializer.

Un tool = une classe

    public function call(array $arguments): array
    {
        $status = $arguments['status'] ?? null;
        $tickets = $status ? $this->tickets->findBy(['status' => $status]) : $this->tickets->findAll();

        return ['content' => [[
            'type' => 'text',
            'text' => $this->serializer->serialize($tickets, 'json'),
        ]]];
    }
}

Le corps de call() est celui de l'ancienne méthode listTickets(), sans aucune modification.

Une erreur d'exécution : GetTicketTool

    public function definition(): array
    {
        return [
            'name' => 'get_ticket',
            'description' => "Récupère le détail d'un ticket à partir de son identifiant.",
            'inputSchema' => [
                'type' => 'object',
                'properties' => ['id' => ['type' => 'integer']],
                'required' => ['id'],
            ],
        ];
    }

    public function call(array $arguments): array
    {
        $ticket = $this->tickets->find($arguments['id'] ?? 0);

        if ($ticket === null) {
            return ['isError' => true, 'content' => [['type' => 'text', 'text' => "Le ticket #{$arguments['id']} n'existe pas."]]];
        }

        return ['content' => [['type' => 'text', 'text' => $this->serializer->serialize($ticket, 'json')]]];
    }
}

Un ticket introuvable n'est pas une erreur de protocole : c'est un résultat avec isError: true, que le modèle peut lire pour se corriger.

Le registre

final class McpToolRegistry
{
    /** @var array<string, McpToolInterface> */
    private array $tools = [];

    /** @param iterable<McpToolInterface> $tools */
    public function __construct(#[AutowireIterator('app.mcp_tool')] iterable $tools)
    {
        foreach ($tools as $tool) {
            $this->tools[$tool->definition()['name']] = $tool;
        }
    }

#[AutowireIterator] injecte tous les services portant le tag app.mcp_tool, sans les lister.

Reference tagged services

Le registre

    public function has(string $name): bool
    {
        return isset($this->tools[$name]);
    }

    public function list(): array
    {
        return array_map(fn (McpToolInterface $tool) => $tool->definition(), array_values($this->tools));
    }

    public function call(string $name, array $arguments): array
    {
        return $this->tools[$name]->call($arguments);
    }
}

Le registre range les tools par nom pour les retrouver lors de tools/call.

Le contrôleur délègue

Les méthodes listTicketsTool() et listTickets() disparaissent du contrôleur, ainsi que le dépôt et le Serializer injectés dans son constructeur.

Ce que nous avons gagné

  • Ajouter un tool = créer une classe, sans toucher au contrôleur ni au registre (principe ouvert/fermé)
  • Chaque tool est testable unitairement avec un dépôt simulé
  • Le contrôleur ne contient plus que le protocole : il pourrait servir à n'importe quelle application

Des classes découvertes automatiquement, un registre, un point d'entrée générique : c'est exactement ce que fait le SDK avec ses attributs #[McpTool].

Pour aller plus loin : un listener

La validation de l'en-tête Origin peut quitter le contrôleur pour un listener sur kernel.request, qui répond 403 avant même le routage :

#[AsEventListener(event: KernelEvents::REQUEST)]
final class McpOriginListener
{
    private const ALLOWED_HOSTS = ['localhost', '127.0.0.1'];

    public function __invoke(RequestEvent $event): void
    {
        $request = $event->getRequest();
        $origin = $request->headers->get('Origin');

        if ($request->getPathInfo() !== '/mcp' || $origin === null) {
            return;
        }

        if (!in_array(parse_url($origin, PHP_URL_HOST), self::ALLOWED_HOSTS, true)) {
            $event->setResponse(new Response(status: Response::HTTP_FORBIDDEN));
        }
    }
}
