Un serveur sans SDK

Objectif

Avant d'utiliser un SDK, écrivons un serveur MCP à la main, en PHP pur, pour voir le protocole à nu.

  • Transport Streamable HTTP, servi par le serveur intégré de PHP (php -S)
  • Ère modern : aucune poignée de main à implémenter
  • Trois méthodes : server/discover, tools/list et tools/call
  • Un seul tool : add, qui additionne deux nombres

Environ 50 lignes suffisent pour qu'un vrai client MCP utilise notre tool.

Ce serveur est pédagogique : il ne valide ni les arguments, ni l'en-tête Origin.

index.php : lire la requête

Le corps de la requête POST contient un message JSON-RPC. La fonction respond() envoie la réponse et arrête le script.

<?php

$request = json_decode(file_get_contents('php://input'), true);
$params = $request['params'] ?? [];

header('Content-Type: application/json');

function respond(array $message, int $status = 200): never
{
    http_response_code($status);
    echo json_encode(['jsonrpc' => '2.0', ...$message]);
    exit;
}
Base protocol

index.php : version et tools

On refuse toute autre version que 2026-07-28, puis on décrit le tool avec un JSON Schema :

$version = $params['_meta']['io.modelcontextprotocol/protocolVersion'] ?? null;
if ($version !== '2026-07-28') {
    respond(['id' => $request['id'] ?? null, 'error' => [
        'code' => -32022,
        'message' => 'Unsupported protocol version',
        'data' => ['supported' => ['2026-07-28'], 'requested' => $version],
    ]], 400);
}

$tools = [[
    'name' => 'add',
    'description' => 'Additionne deux nombres',
    'inputSchema' => [
        'type' => 'object',
        'properties' => ['a' => ['type' => 'number'], 'b' => ['type' => 'number']],
        'required' => ['a', 'b'],
    ],
]];
Versioning

index.php : router les méthodes

Un match associe chaque méthode à son résultat ; toute autre méthode renvoie 404 et -32601 :

$result = match ($request['method']) {
    'server/discover' => [
        'supportedVersions' => ['2026-07-28'],
        'capabilities' => ['tools' => new stdClass()],
        '_meta' => ['io.modelcontextprotocol/serverInfo' => ['name' => 'calculator', 'version' => '1.0.0']],
        'ttlMs' => 3600000,
        'cacheScope' => 'public',
    ],
    'tools/list' => ['tools' => $tools, 'ttlMs' => 3600000, 'cacheScope' => 'public'],
    'tools/call' => [
        'content' => [['type' => 'text', 'text' => (string) ($params['arguments']['a'] + $params['arguments']['b'])]],
        'isError' => false,
    ],
    default => respond(['id' => $request['id'], 'error' => ['code' => -32601, 'message' => 'Method not found']], 404),
};

respond(['id' => $request['id'], 'result' => ['resultType' => 'complete', ...$result]]);
Tools

Lancer et tester

On démarre le serveur intégré de PHP, puis on interroge server/discover :

php -S localhost:8000 index.php
curl -X POST http://localhost:8000 \
  -H 'Content-Type: application/json' \
  -H 'Accept: application/json, text/event-stream' \
  -H 'MCP-Protocol-Version: 2026-07-28' \
  -H 'Mcp-Method: server/discover' \
  -d '{"jsonrpc": "2.0", "id": 1, "method": "server/discover",
       "params": {"_meta": {"io.modelcontextprotocol/protocolVersion": "2026-07-28", "io.modelcontextprotocol/clientCapabilities": {}}}}'

Les en-têtes MCP-Protocol-Version et Mcp-Method sont exigés par la spécification ; notre serveur minimal ne les vérifie pas.

Request metadata

Appeler le tool

curl -X POST http://localhost:8000 \
  -H 'Content-Type: application/json' \
  -H 'Accept: application/json, text/event-stream' \
  -H 'MCP-Protocol-Version: 2026-07-28' \
  -H 'Mcp-Method: tools/call' -H 'Mcp-Name: add' \
  -d '{"jsonrpc": "2.0", "id": 3, "method": "tools/call",
       "params": {"name": "add", "arguments": {"a": 2, "b": 40}, "_meta": {"io.modelcontextprotocol/protocolVersion": "2026-07-28", "io.modelcontextprotocol/clientCapabilities": {}}}}'

Réponse :

{"jsonrpc":"2.0","id":3,"result":{"resultType":"complete","content":[{"type":"text","text":"42"}],"isError":false}}

Le client (ou le modèle) lit le contenu text du résultat. isError: false indique que le tool s'est exécuté sans erreur.

Calling tools

Un vrai client : l'Inspector

L'Inspector se connecte à notre serveur en ère modern grâce à un fichier de configuration :

{
  "mcpServers": {
    "calculator": { "type": "http", "url": "http://localhost:8000", "protocolEra": "modern" }
  }
}
npx @modelcontextprotocol/inspector --cli --config inspector.json --server calculator \
  --method tools/call --tool-name add --tool-arg a=2 --tool-arg b=40

Par défaut, l'Inspector utilise l'ère legacy et commencerait par initialize, que notre serveur ne connaît pas.

Exercice

Écrivez votre propre serveur sans SDK.

  1. Créez index.php et lancez-le avec php -S localhost:8000 index.php.
  2. Testez server/discover, tools/list et tools/call avec curl.
  3. Ajoutez un tool multiply et vérifiez qu'il apparaît dans tools/list.
  4. Envoyez une méthode inconnue, puis une autre version du protocole : observez codes HTTP et erreurs.
  5. Appelez vos tools depuis l'Inspector en ère modern.
  6. Bonus : renvoyez une erreur de tool (isError: true) quand un argument n'est pas un nombre.

Ce que le SDK fera pour nous

Notre serveur fonctionne, mais il manque beaucoup de choses qu'un SDK prend en charge :

  • Générer le inputSchema à partir des types PHP et valider les arguments
  • Vérifier les en-têtes, l'en-tête Origin et la version demandée
  • Servir les deux ères (legacy et modern) avec le même code
  • Gérer le transport stdio, les erreurs, le cache, l'elicitation…

Avec le SDK, on n'écrit plus que le code métier : les tools, les resources et les prompts.
