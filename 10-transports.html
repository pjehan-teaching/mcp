Transport types

Activer stdio

# config/packages/mcp.yaml
mcp:
    servers:
        default:
            # …
            transports:
                stdio: true
                http: true
{
    "servers": {
        "tickets-stdio": {
            "type": "stdio",
            "command": "php",
            "args": ["${workspaceFolder}/bin/console", "mcp:server"]
        }
    }
}
npx @modelcontextprotocol/inspector --cli php bin/console mcp:server --method tools/list

En stdio, un dump() ou un echo corrompt le flux : journalisez sur le canal mcp de Monolog.

MCP configuration reference

Une seule URL, deux ères

Le transport HTTP examine chaque requête et choisit l'ère qui y répond :

IndiceÈre
_meta annonce 2026-07-28modern
initialize, ou en-tête Mcp-Session-Id d'une session ouvertelegacy
  • L'ère legacy a besoin de sessions : le bundle les stocke dans var/cache/<env>/mcp-sessions/default par défaut
  • L'ère modern n'en a pas besoin : chaque requête se suffit à elle-même

Bundle configuration

Accepter d'autres domaines

Par défaut, le transport n'accepte que les requêtes dont l'en-tête Origin ou Host désigne localhost : c'est la protection contre le DNS rebinding exigée par la spécification.

mcp:
    servers:
        default:
            http:
                path: /mcp
                allowed_hosts: ['tickets.example.com']
  • allowed_hosts remplace la liste par défaut
  • allowed_hosts: false désactive la protection, par exemple derrière un proxy qui valide déjà Host

C'est l'équivalent du McpOriginListener écrit à la main dans tickets-raw.

DNS rebinding protection

Plusieurs serveurs dans une application

mcp:
    servers:
        public:
            name: 'tickets'
            http: { path: /mcp }
            registry:
                tools: ['App\Mcp\ReadOnly\']
        support:
            name: 'tickets-support'
            http: { path: /mcp/support }
            registry: '*'

# config/packages/security.yaml
security:
    access_control:
        - { path: ^/mcp/support, roles: ROLE_SUPPORT }
  • Chaque serveur a sa route, son identité et sa liste de capacités (registry)
  • L'accès se protège avec la sécurité Symfony habituelle
Multiple servers

Restreindre les versions

Par défaut, le serveur accepte toutes les versions connues du SDK. protocol_versions limite cette liste :

mcp:
    servers:
        default:
            protocol_versions: ['2025-11-25', '2026-07-28']
  • Ne lister que des versions legacy refuse l'ère modern
  • Utile si un handler s'appuie encore sur Sampling ou Roots, supprimés en ère modern

Exercice

Servez le fil rouge sur les deux transports.

  1. Activez le transport stdio et listez les tools avec l'Inspector en ligne de commande.
  2. Déclarez tickets-stdio dans .vscode/mcp.json à côté du serveur HTTP : comparez les deux dans Copilot.
  3. Ouvrez var/cache/dev/mcp-sessions/default après une connexion de VS Code, puis après un appel en ère modern.
  4. Envoyez avec curl une requête portant -H 'Origin: https://evil.example' : quel code HTTP obtenez-vous ?
  5. Bonus : déclarez un second serveur /mcp/support qui n'expose que les tools d'écriture.
