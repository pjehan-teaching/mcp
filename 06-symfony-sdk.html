Le SDK et symfony/mcp-bundle

Le SDK PHP officiel

  • Paquet Composer mcp/sdk, développé par la PHP Foundation et le projet Symfony
  • SDK officiel de niveau 3, en version 0.8 : expérimental jusqu'à la version 1.0
  • Ères legacy et modern servies par le même code
  • Déclaration des tools, resources et prompts par attributs PHP

Le bundle symfony/mcp-bundle (version 0.14) l'intègre à Symfony : route, configuration, conteneur de services, commandes.

Le SDK et le bundle sont expérimentaux : leur API peut encore changer d'une version à l'autre.

Installation

Configurer le serveur

Le bundle n'a pas de recette Flex : les deux fichiers s'écrivent à la main.

# config/packages/mcp.yaml
mcp:
    servers:
        default:
            name: 'tickets'
            version: '1.0.0'
            http:
                path: /mcp
            registry: '*'
# config/routes.yaml
controllers:
    resource: routing.controllers

mcp:
    resource: .
    type: mcp
  • Le bundle enregistre lui-même la route /mcp : plus de contrôleur à écrire
  • registry: '*' expose tous les tools, resources et prompts de l'application
Act as Server

Les tools : TicketTools

<?php

namespace App\Mcp;

use App\Repository\TicketRepository;
use Mcp\Capability\Attribute\McpTool;
use Mcp\Capability\Attribute\Schema;
use Mcp\Exception\ToolCallException;
use Symfony\Component\Serializer\Normalizer\NormalizerInterface;

final class TicketTools
{
    public function __construct(
        private readonly TicketRepository $tickets,
        private readonly NormalizerInterface $normalizer,
    ) {
    }

    /**
     * Liste les tickets de support, éventuellement filtrés par statut.
     */
    #[McpTool(name: 'list_tickets')]
    public function list(#[Schema(enum: ['open', 'closed'])] ?string $status = null): array
    {
        $tickets = $status ? $this->tickets->findBy(['status' => $status]) : $this->tickets->findAll();

        return ['tickets' => $this->normalizer->normalize($tickets)];
    }

    /**
     * Récupère le détail d'un ticket à partir de son identifiant.
     */
    #[McpTool(name: 'get_ticket')]
    public function get(int $id): array
    {
        $ticket = $this->tickets->find($id) ?? throw new ToolCallException("Le ticket #$id n'existe pas.");

        return $this->normalizer->normalize($ticket);
    }
}

Ces 40 lignes remplacent le contrôleur, l'interface, le registre et les deux classes de tools.

Ce que fait le SDK

  • #[McpTool] transforme la méthode en tool ; sans name, son nom est celui de la méthode
  • Le docblock devient la description du tool
  • Les types des paramètres deviennent le inputSchema : int $id donne un entier obligatoire ; #[Schema] ajoute des contraintes
  • Le SDK valide les arguments reçus avant d'appeler la méthode
  • Un tableau renvoyé devient un contenu texte JSON et un structuredContent
  • ToolCallException produit un résultat isError: true ; toute autre exception, une erreur JSON-RPC au message générique

Toute classe de src/ portant un attribut MCP est détectée à la compilation du conteneur : TicketTools reçoit le dépôt et le normalizer par autowiring.

Tester dans les deux ères

On lance le serveur comme avant, puis on déclare deux connexions dans inspector.json :

{
  "mcpServers": {
    "tickets": { "type": "http", "url": "http://localhost:8000/mcp", "protocolEra": "modern" },
    "tickets-legacy": { "type": "http", "url": "http://localhost:8000/mcp" }
  }
}
npx @modelcontextprotocol/inspector --cli --config inspector.json --server tickets \
  --method tools/call --tool-name list_tickets --tool-arg status=closed
npx @modelcontextprotocol/inspector --cli --config inspector.json --server tickets-legacy \
  --method tools/list

La même URL répond aux deux ères : le transport examine chaque requête et choisit l'ère qui y répond.

Exercice

  1. Créez le projet tickets, installez les paquets et copiez l'entité, le dépôt, les fixtures et .env.local.

  3. Appelez list_tickets et get_ticket depuis l'Inspector, en ère modern puis legacy.
  4. Rejouez vos requêtes curl d'erreur du chapitre « Le protocole » : comparez les réponses avec celles de tickets-raw.
  5. Branchez le serveur dans VS Code et interrogez-le depuis Copilot.
