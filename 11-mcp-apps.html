Extensions overview

Négocier une extension

Client, à chaque requête

"_meta": {
  "io.modelcontextprotocol/clientCapabilities": {
    "extensions": {
      "io.modelcontextprotocol/ui": {
        "mimeTypes": ["text/html;profile=mcp-app"]
      }
    }
  }
}

Serveur, dans server/discover

"capabilities": {
  "tools": {},
  "resources": {},
  "extensions": {
    "io.modelcontextprotocol/ui": {
      "mimeTypes": ["text/html;profile=mcp-app"]
    }
  }
}

Un serveur peut vérifier la prise en charge avant de s'appuyer sur une extension : $context->getClientGateway()->supportsExtension(McpApps::EXTENSION_ID).

Negotiation

MCP Apps

Un tool peut afficher une interface HTML interactive directement dans la conversation : tableau de bord, formulaire, visualisation…

  • Contexte conservé : l'interface vit dans la conversation, sans changer d'onglet
  • Échanges dans les deux sens : la vue appelle les tools du serveur via le host
  • Sécurité : la vue s'exécute dans un iframe isolé, sans accès à la page du host

Pris en charge par Claude, VS Code + GitHub Copilot, ChatGPT, Cursor, Goose…

La vue et le host communiquent par postMessage avec des messages JSON-RPC : ui/initialize, ui/notifications/tool-result, tools/call…

ext-apps

Côté serveur : la resource UI

class TicketDashboard
{
    public function __construct(private TicketRepository $tickets)
    {
    }

    #[McpResource(
        uri: 'ui://tickets/dashboard',
        name: 'dashboard',
        mimeType: McpApps::MIME_TYPE,
        meta: ['ui' => new \stdClass()],
    )]
    public function view(): TextResourceContents
    {
        return new TextResourceContents(
            uri: 'ui://tickets/dashboard',
            mimeType: McpApps::MIME_TYPE,
            text: file_get_contents(__DIR__ . '/../dashboard.html'),
        );
    }

Schéma ui:// et type text/html;profile=mcp-app (McpApps::MIME_TYPE).

Côté serveur : le tool lié

    /**
     * Affiche le tableau de bord interactif des tickets.
     */
    #[McpTool(
        name: 'show_dashboard',
        annotations: new ToolAnnotations(readOnlyHint: true),
        meta: ['ui' => new UiToolMeta(resourceUri: 'ui://tickets/dashboard')],
    )]
    public function show(): array
    {
        return ['tickets' => $this->tickets->findAll()];
    }
}

UiToolMeta ajoute à la définition du tool : "_meta": {"ui": {"resourceUri": "ui://tickets/dashboard"}}.

Activer l'extension

<?php

require __DIR__ . '/vendor/autoload.php';

use Mcp\Schema\Extension\Apps\McpApps;
use Mcp\Server;
use Mcp\Server\Transport\StdioTransport;

exit(Server::builder()
    ->setServerInfo('Tickets', '1.0.0')
    ->setDiscovery(__DIR__, ['src'])
    ->enableExtension(new McpApps())
    ->build()
    ->run(new StdioTransport()));

Sans enableExtension(), les hosts n'affichent que le résultat texte.

SDK : Protocol extensions

La vue HTML : échanger avec le host

<!DOCTYPE html>
<html lang="fr">
<body>
    <h1>Tickets</h1>
    <table id="tickets"></table>
    <button id="refresh">Rafraîchir</button>

    <script>
        let nextId = 1;
        const pending = new Map();

        function request(method, params) {
            const id = nextId++;
            window.parent.postMessage({ jsonrpc: '2.0', id, method, params }, '*');
            return new Promise(resolve => pending.set(id, resolve));
        }

request() envoie une requête JSON-RPC au host et renvoie une promesse résolue à la réception de la réponse.

La vue HTML : afficher les tickets

        function render(result) {
            const table = document.getElementById('tickets');
            table.replaceChildren();
            for (const ticket of result.structuredContent.tickets) {
                const row = table.insertRow();
                for (const value of [`#${ticket.id}`, ticket.title, ticket.status]) {
                    row.insertCell().textContent = value; // Jamais innerHTML : le titre vient d'un client
                }
            }
        }

        window.addEventListener('message', ({ data }) => {
            if (pending.has(data.id)) {
                pending.get(data.id)(data.result);
                pending.delete(data.id);
            } else if (data.method === 'ui/notifications/tool-result') {
                render(data.params);
            }
        });

textContent et non innerHTML : les titres sont saisis par des clients.

La vue HTML : initialiser et rafraîchir

        document.getElementById('refresh').addEventListener('click', async () => {
            render(await request('tools/call', { name: 'show_dashboard', arguments: {} }));
        });

        request('ui/initialize', {
            protocolVersion: '2026-01-26',
            appInfo: { name: 'tickets-dashboard', version: '1.0.0' },
            appCapabilities: {},
        }).then(() => {
            window.parent.postMessage({ jsonrpc: '2.0', method: 'ui/notifications/initialized' }, '*');
        });

La vue commence par ui/initialize, puis signale qu'elle est prête avec ui/notifications/initialized : le host lui envoie alors le résultat du tool.

Tester l'application

  • Dans VS Code, demandez : « Affiche le tableau de bord des tickets »
  • Le résultat du tool s'affiche dans l'interface, puis le bouton Rafraîchir rappelle le tool
  • L'Inspector vérifie la liaison entre tool et resource :
npx @modelcontextprotocol/inspector --cli php server.php --method tools/list --app-info

Pour des applications plus riches, le SDK TypeScript @modelcontextprotocol/ext-apps gère le protocole de la vue.

Exercice

Ajoutez un tableau de bord interactif au fil rouge.

  1. Créez dashboard.html et src/TicketDashboard.php, puis activez l'extension dans server.php et http.php.
  2. Vérifiez avec l'Inspector que show_dashboard est bien lié à ui://tickets/dashboard.
  3. Affichez le tableau de bord depuis Copilot, fermez un ticket dans la conversation puis cliquez sur Rafraîchir.
  4. Créez un ticket dont le titre contient du HTML : vérifiez qu'il s'affiche comme du texte.
  5. Bonus : un bouton Fermer par ticket qui appelle close_ticket depuis la vue.
