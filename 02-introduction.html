Pourquoi MCP

Un modèle isolé

Un modèle de langage ne connaît que ses données d'entraînement et le contenu de la conversation.

Pour être vraiment utile, il doit pouvoir :

  • lire des données à jour : fichiers, base de données, tickets, documentation…
  • agir sur des systèmes externes : créer un ticket, envoyer un e-mail, ouvrir une pull request…

Chaque application d'IA a longtemps développé ses propres connecteurs vers chaque service.

Le problème N×M

Sans protocole commun

Chaque application d'IA intègre chaque service à sa façon.

4 applications × 10 services = 40 intégrations à écrire et maintenir.

Avec MCP

Chaque application implémente un client, chaque service un serveur.

4 clients + 10 serveurs = 14 implémentations, toutes compatibles entre elles.

Un serveur MCP écrit une fois fonctionne dans tous les hosts compatibles.

Model Context Protocol

MCP est un standard ouvert pour connecter des applications d'IA à des systèmes externes : sources de données, services et workflows.

  • Créé par Anthropic, publié en open source le 25 novembre 2024
  • Spécification versionnée par date : 2024-11-05, 2025-03-26, 2025-06-18, 2025-11-25, 2026-07-28
  • Évolutions proposées et discutées publiquement sous forme de SEP (Specification Enhancement Proposals)

Architecture : host, client, serveur

  • Host : l'application utilisée par l'utilisateur, qui embarque le modèle (VS Code, Claude Desktop…)
  • Client : composant du host qui maintient la connexion avec un serveur
  • Serveur : programme qui expose des fonctionnalités et des données au client
┌───────── Host (VS Code) ─────────┐
│                                  │
│  Modèle ─┬─ Client 1 ────────────┼──► Serveur filesystem (local, stdio)
│          ├─ Client 2 ────────────┼──► Serveur GitHub (distant, HTTP)
│          └─ Client 3 ────────────┼──► Serveur tickets (local, stdio)
│                                  │
└──────────────────────────────────┘

Le host crée un client par serveur connecté.

Transports

Deux couches

Couche données

  • Messages JSON-RPC 2.0
  • Découverte du serveur
  • Primitives : tools, resources, prompts
  • Elicitation, notifications

Couche transport

  • stdio : entrée et sortie standard
  • Streamable HTTP : requêtes POST
  • Autorisation (HTTP uniquement)

Les mêmes messages JSON-RPC circulent quel que soit le transport.

Understanding MCP servers

Côté client : l'elicitation

Un serveur peut avoir besoin d'une information de l'utilisateur pendant le traitement d'une requête :

  • confirmer une action destructrice
  • compléter une information manquante
  • choisir parmi plusieurs options

C'est l'elicitation : le serveur formule la demande, le client l'affiche à l'utilisateur et renvoie sa réponse.

D'autres fonctionnalités client existent encore (Sampling, Roots, Logging) mais sont dépréciées depuis 2026-07-28.

Brancher un serveur dans VS Code

Le fichier .vscode/mcp.json déclare les serveurs du projet :

{
    "servers": {
        "filesystem": {
            "command": "npx",
            "args": ["-y", "@modelcontextprotocol/server-filesystem", "${workspaceFolder}"]
        }
    }
}
  • command et args : la commande qui lance un serveur local (stdio)
  • Un serveur distant se déclare avec "type": "http" et "url"
  • La commande MCP: List Servers permet de démarrer, arrêter et consulter les logs d'un serveur
MCP servers in VS Code

Observer avec l'Inspector

L'Inspector lance le serveur et se comporte comme un client, sans modèle :

npx @modelcontextprotocol/inspector npx -y @modelcontextprotocol/server-filesystem .
  • onglet Tools : lister les tools et les appeler avec un formulaire
  • onglets Resources et Prompts : les autres primitives
  • historique des échanges : chaque requête et chaque réponse JSON-RPC

Il existe aussi en ligne de commande (--cli) et en interface terminal (--tui).

Exercice

Vous allez brancher le serveur officiel filesystem dans VS Code, puis observer les mêmes échanges dans l'Inspector.

  1. Installez Node.js 22.19+, VS Code et GitHub Copilot.
  2. Ouvrez dans VS Code un dossier contenant un README.md.
  3. Déclarez le serveur filesystem dans .vscode/mcp.json.
  4. En mode agent, demandez : « Résume le README du projet ». Observez les tools appelés.
  5. Dans l'Inspector, appelez list_directory puis read_text_file.
  6. Qui a choisi les tools et leurs arguments dans chaque cas ?
