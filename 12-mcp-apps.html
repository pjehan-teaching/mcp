Extensions overview

Négocier une extension

Client, à chaque requête

"_meta": {
  "io.modelcontextprotocol/clientCapabilities": {
    "extensions": {
      "io.modelcontextprotocol/ui": {
        "mimeTypes": ["text/html;profile=mcp-app"]
      }
    }
  }
}

Serveur, dans server/discover

"capabilities": {
  "tools": {},
  "resources": {},
  "extensions": {
    "io.modelcontextprotocol/ui": {
      "mimeTypes": ["text/html;profile=mcp-app"]
    }
  }
}

Un serveur peut vérifier la prise en charge avant de s'appuyer sur une extension : $context->getClientGateway()->supportsExtension(McpApps::EXTENSION_ID).

Negotiation

MCP Apps

Un tool peut afficher une interface HTML interactive directement dans la conversation : tableau de bord, formulaire, visualisation…

  • Contexte conservé : l'interface vit dans la conversation, sans changer d'onglet
  • Échanges dans les deux sens : la vue appelle les tools du serveur via le host
  • Sécurité : la vue s'exécute dans un iframe isolé, sans accès à la page du host

Pris en charge par Claude, VS Code + GitHub Copilot, ChatGPT, Cursor, Goose…

La vue et le host communiquent par postMessage avec des messages JSON-RPC : ui/initialize, ui/notifications/tool-result, tools/call…

ext-apps

Une app = une classe

Le bundle fournit l'attribut #[AsMcpApp] (composer require symfony/twig-bundle) :

<?php

namespace App\Mcp;

use App\Repository\TicketRepository;
use Symfony\AI\McpBundle\Attribute\AsMcpApp;
use Symfony\Component\Serializer\Normalizer\NormalizerInterface;

#[AsMcpApp(
    uri: 'ui://tickets/dashboard',
    name: 'show_dashboard',
    title: 'Tickets',
    description: 'Affiche le tableau de bord interactif des tickets.',
    template: 'mcp/dashboard.html.twig',
    toolTemplate: 'mcp/_tickets.html.twig',
)]
final class TicketDashboard
{
    public function __construct(
        private readonly TicketRepository $tickets,
        private readonly NormalizerInterface $normalizer,
    ) {
    }

    public function render(): array
    {
        return ['tickets' => $this->normalizer->normalize($this->tickets->findAll())];
    }
}

Les tickets sont normalisés : le tableau renvoyé sert aussi de structuredContent, et un objet aux propriétés privées y deviendrait {}.

Bundle : MCP Apps

Ce que fait #[AsMcpApp]

  • Enregistre la resource ui://tickets/dashboard, de type text/html;profile=mcp-app, à partir de template
  • Enregistre le tool show_dashboard, dont le résultat est renvoyé par render() et le schéma déduit de sa signature
  • Lie le tool à la vue dans sa définition :
"_meta": {
  "ui": { "resourceUri": "ui://tickets/dashboard", "visibility": ["model", "app"] }
}
  • Active l'extension io.modelcontextprotocol/ui dans les capacités du serveur
  • Rend toolTemplate avec le tableau renvoyé, et l'ajoute au résultat dans un champ html
MCP Apps

La vue : deux templates Twig

{# templates/mcp/dashboard.html.twig #}
{% extends '@Mcp/app/base.html.twig' %}

{% block style %}
    table { border-collapse: collapse; font: 0.9rem system-ui; }
    td { padding: 0.25rem 0.5rem; border-bottom: 1px solid #ddd; }
{% endblock %}

La coquille : lue une seule fois par le host, elle reste statique.

{# templates/mcp/_tickets.html.twig #}
<table>
    {% for ticket in tickets %}
        <tr>
            <td>#{{ ticket.id }}</td>
            <td>{{ ticket.title }}</td>
            <td>{{ ticket.status }}</td>
        </tr>
    {% endfor %}
</table>
<button data-call="show_dashboard">Rafraîchir</button>

Le fragment : rendu à chaque appel du tool, injecté dans la coquille.

Twig échappe les titres : un ticket dont le titre contient du HTML s'affiche comme du texte.

Rendering with Twig

Ce que fait le template de base

@Mcp/app/base.html.twig implémente le dialogue avec le host, par postMessage et messages JSON-RPC :

  1. la vue envoie ui/initialize, puis ui/notifications/initialized quand elle est prête
  2. le host lui transmet le résultat du tool avec ui/notifications/tool-result
  3. la fonction render(model) injecte model.html dans l'élément #root
  4. un élément data-call="…" déclenche un tools/call, relayé par le host vers le serveur
  5. la vue signale sa taille avec ui/notifications/size-changed

Pour une interface très riche, on peut surcharger le bloc app_script et écrire son propre JavaScript.

ext-apps

Rendre la vue interactive

Un tool réservé à la vue s'ajoute sur une méthode de la même classe :

    #[AsMcpAppTool(name: 'filter_dashboard', template: 'mcp/_tickets.html.twig', appOnly: true)]
    public function filter(string $status): array
    {
        return ['tickets' => $this->normalizer->normalize($this->tickets->findBy(['status' => $status]))];
    }
<button data-call="filter_dashboard" data-arg-status="open">Ouverts</button>
  • appOnly: true : le tool est appelable par la vue, mais absent de la liste vue par le modèle ("visibility": ["app"])
  • data-arg-status devient l'argument status ; le fragment renvoyé remplace le contenu de #root

Tester l'application

  • Dans VS Code, demandez : « Affiche le tableau de bord des tickets »
  • Le résultat du tool s'affiche dans la vue, puis le bouton Rafraîchir rappelle le tool
  • L'Inspector vérifie la liaison entre tool et resource :
npx @modelcontextprotocol/inspector --cli --config inspector.json --server tickets \
  --method tools/list --app-info
{"hasApp":true,"toolName":"show_dashboard","resourceUri":"ui://tickets/dashboard","visibility":["model","app"],…}
{"hasApp":true,"toolName":"filter_dashboard","resourceUri":"ui://tickets/dashboard","visibility":["app"],…}
{"hasApp":false,"toolName":"list_tickets"}
Build an MCP App

Exercice

Ajoutez un tableau de bord interactif au fil rouge.

  1. Installez symfony/twig-bundle, créez src/Mcp/TicketDashboard.php et ses deux templates Twig.
  2. Vérifiez avec l'Inspector que show_dashboard est bien lié à ui://tickets/dashboard.
  3. Affichez le tableau de bord depuis Copilot, fermez un ticket dans la conversation puis cliquez sur Rafraîchir.
  4. Créez un ticket dont le titre contient du HTML : vérifiez qu'il s'affiche comme du texte.
  5. Bonus : des boutons Ouverts et Fermés qui filtrent la liste avec un #[AsMcpAppTool].
