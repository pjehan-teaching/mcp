Serveur HTTP

Pourquoi passer en HTTP ?

  • Rendre le serveur accessible à distance, sans installation chez l'utilisateur
  • Servir plusieurs clients simultanément
  • Déployer plusieurs instances derrière un répartiteur de charge : l'ère modern ne demande aucun état partagé
  • Protéger l'accès avec une autorisation OAuth (chapitre suivant)
  • Et, avec le SDK PHP 0.8 : servir l'ère modern, que le transport stdio ne gère pas
Streamable HTTP

Dépendances

Le transport HTTP du SDK manipule des requêtes et réponses PSR-7. Il lui faut une implémentation et un émetteur de réponse :

composer require nyholm/psr7 laminas/laminas-httphandlerrunner
  • nyholm/psr7 : objets requête et réponse, découverts automatiquement
  • laminas/laminas-httphandlerrunner : envoie la réponse PSR-7 au navigateur ou au client
SDK : HTTP transport

http.php

<?php

require __DIR__ . '/vendor/autoload.php';

use Http\Discovery\Psr17Factory;
use Laminas\HttpHandlerRunner\Emitter\SapiEmitter;
use Mcp\Server;
use Mcp\Server\Session\FileSessionStore;
use Mcp\Server\Transport\StreamableHttpTransport;

$request = (new Psr17Factory())->createServerRequestFromGlobals();

$response = Server::builder()
    ->setServerInfo('Tickets', '1.0.0')
    ->setDiscovery(__DIR__, ['src'])
    ->setSession(new FileSessionStore(__DIR__ . '/sessions'))
    ->build()
    ->run(new StreamableHttpTransport($request));

(new SapiEmitter())->emit($response);
SDK : HTTP

Une seule URL, deux ères

Le transport examine chaque requête et choisit l'ère qui y répond :

IndiceÈre
_meta annonce 2026-07-28modern
_meta annonce une version plus ancienne, ou pas de _meta (initialize)legacy
Requête GET ou DELETElegacy
  • FileSessionStore sert uniquement à l'ère legacy : chaque requête est traitée par un nouveau processus PHP
  • Par défaut, le transport refuse les origines croisées et n'accepte que localhost (protection contre le DNS rebinding)

MCP configuration reference

Accepter d'autres domaines

Derrière un nom de domaine, déclarez les domaines autorisés, sinon le serveur répond 403 :

use Mcp\Server\Transport\Http\Middleware\CorsMiddleware;
use Mcp\Server\Transport\Http\Middleware\DnsRebindingProtectionMiddleware;

new StreamableHttpTransport($request, middleware: [
    new CorsMiddleware(),
    new DnsRebindingProtectionMiddleware(allowedHosts: ['tickets.example.com']),
]);

Dans une application Symfony ou Laravel, le transport s'intègre dans un contrôleur via les passerelles PSR-7 du framework.

DNS rebinding protection Framework integration

Intégrer MCP dans Symfony

# config/packages/mcp.yaml
mcp:
    servers:
        default:
            name: 'tickets'
            transports:
                stdio: true
                http: true
            http:
                path: /mcp
            registry: '*'

# config/routes.yaml
mcp:
    resource: .
    type: mcp
  • Bundle officiel symfony/mcp-bundle, basé sur mcp/sdk
  • Déclaration des serveurs, transports et capacités en configuration
  • Les services portant #[McpTool], #[McpResource]… sont détectés automatiquement
  • Expérimental, comme le SDK
composer require symfony/mcp-bundle

Exercice

Rendez le fil rouge accessible en HTTP.

  1. Installez les dépendances et créez http.php.
  2. Lancez php -S localhost:8000 http.php et connectez l'Inspector en ère legacy, puis modern.
  3. En ère modern, fermez un ticket et retrouvez l'échange input_required dans l'historique.
  4. Remplacez le serveur stdio par le serveur HTTP dans .vscode/mcp.json et testez depuis Copilot.
  5. Bonus : envoyez avec curl une requête dont l'en-tête Mcp-Method contredit le corps, et observez l'erreur.
