Resources et prompts

Resources

Une resource est une donnée identifiée par une URI, que le serveur met à disposition en lecture.

  • Fichiers, enregistrements, schéma d'une base de données, documentation…
  • Contrôlée par l'application : le host décide quand l'ajouter au contexte, souvent sur choix de l'utilisateur
  • Contenu texte (text) ou binaire encodé en base64 (blob), avec un mimeType
  • URI standard (https://, file://) ou schéma personnalisé (ticket://)

Dans VS Code : Add Context > MCP Resources.

Les templates suivent la syntaxe des URI templates (RFC 6570). Leurs variables peuvent être autocomplétées.

Resource templates

Déclarer une resource template

final class TicketResources
{
    public function __construct(
        private readonly TicketRepository $tickets,
        private readonly NormalizerInterface $normalizer,
    ) {
    }

    /**
     * Détail complet d'un ticket de support.
     */
    #[McpResourceTemplate(uriTemplate: 'ticket://{id}', name: 'ticket', mimeType: 'application/json')]
    public function ticket(string $id): array
    {
        $ticket = $this->tickets->find((int) $id) ?? throw new ResourceNotFoundException("ticket://$id");

        return $this->normalizer->normalize($ticket);
    }

Les variables de l'URI sont liées aux paramètres par leur nom ; une variable ne peut pas contenir /.

Prompts

Un prompt est un modèle de message paramétré que le serveur propose à l'utilisateur.

  • Contrôlé par l'utilisateur : il le choisit explicitement, souvent sous forme de commande /
  • Arguments facultatifs ou obligatoires, autocomplétés par le serveur
  • Le résultat est une liste de messages, avec les rôles user ou assistant (pas de rôle system)
  • Le contenu est défini par le serveur : il peut embarquer des données fraîches

Dans VS Code : tapez /tickets.triage_tickets dans le chat.

Prompts

Déclarer un prompt

    /**
     * Trie les tickets ouverts par priorité.
     */
    #[McpPrompt(name: 'triage_tickets')]
    public function triage(
        #[CompletionProvider(values: ['technique', 'facturation'])] string $focus = 'technique',
    ): array {
        $open = $this->normalizer->normalize($this->tickets->findBy(['status' => 'open']));
        $tickets = json_encode($open, JSON_UNESCAPED_UNICODE);

        return [
            ['role' => 'user', 'content' => "Voici les tickets ouverts : $tickets\n"
                . "Classe-les du plus urgent au moins urgent (focus : $focus), "
                . 'puis propose un assigné pour chacun.'],
        ];
    }
SDK : Prompts

Obtenir un prompt

prompts/get avec {"name": "triage_tickets", "arguments": {"focus": "facturation"}} renvoie :

{
  "messages": [{
    "role": "user",
    "content": {
      "type": "text",
      "text": "Voici les tickets ouverts :\n[…]\n\nClasse-les du plus urgent au moins urgent…"
    }
  }]
}

Le host insère ces messages dans la conversation, puis le modèle répond.

Getting a prompt

Autocomplétion

completion/complete propose des valeurs pour un argument de prompt ou une variable de resource template :

{
  "method": "completion/complete",
  "params": {
    "ref": { "type": "ref/prompt", "name": "triage_tickets" },
    "argument": { "name": "focus", "value": "fa" }
  }
}
{
  "completion": { "values": ["facturation"], "total": 1, "hasMore": false }
}

Le SDK accepte une liste (values), une enum PHP (enum) ou une classe (provider). Validez toujours les valeurs reçues.

Mettre en cache avec le bundle

Rappel du chapitre « Le protocole » : server/discover, les listes et resources/read indiquent leur durée de validité (ttlMs) et leur portée (cacheScope).

Le bundle refuse le cache par défaut (ttlMs: 0). On l'active par méthode dans mcp.yaml :

mcp:
    servers:
        default:
            # …
            cache:
                ttl_ms: 0
                scope: private
                methods:
                    'server/discover': { ttl_ms: 3600000, scope: public }
                    'tools/list': { ttl_ms: 3600000, scope: public }

N'utilisez public que pour des réponses identiques pour tous les utilisateurs.

Être notifié des changements

Un client ouvre un flux de notifications avec subscriptions/listen, en précisant ce qui l'intéresse :

{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "subscriptions/listen",
  "params": {
    "_meta": { … },
    "notifications": {
      "toolsListChanged": true,
      "resourceSubscriptions": ["ticket://2"]
    }
  }
}

Le serveur confirme par notifications/subscriptions/acknowledged, puis envoie les notifications demandées sur ce flux SSE, qui reste ouvert.

Avec le bundle, la diffusion passe par un bus (subscriptions.bus dans mcp.yaml) : cache sous PHP-FPM, où le processus qui publie n'est pas celui qui tient le flux.

Enrichissez le fil rouge avec une resource et un prompt.

  1. Créez src/Mcp/TicketResources.php avec la resource template ticket://{id}.
  2. Lisez ticket://2 puis ticket://99 dans l'Inspector : observez le contenu et l'erreur.

  6. Bonus : configurez le cache pour garder tools/list une heure, et vérifiez ttlMs avec curl.
