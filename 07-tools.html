Tools

Rappel : un tool

Un tool est une fonction exposée par le serveur, que le modèle décide d'appeler avec des arguments.

  • tools/list : le client récupère la liste des tools et la transmet au modèle
  • tools/call : le client exécute l'appel choisi par le modèle
  • Le résultat est renvoyé au modèle, qui poursuit sa réponse

Un humain doit toujours pouvoir refuser l'appel d'un tool : les hosts affichent les tools utilisés et demandent confirmation pour les opérations sensibles.

Tools

Définition d'un tool

{
  "name": "list_tickets",
  "description": "Liste les tickets de support, éventuellement filtrés par statut.",
  "inputSchema": {
    "type": "object",
    "properties": {
      "status": { "type": ["null", "string"], "default": null, "enum": ["open", "closed"] }
    }
  },
  "annotations": { "readOnlyHint": true }
}
  • name : identifiant unique ; title : nom affiché ; description : ce que fait le tool
  • inputSchema : JSON Schema des arguments ; outputSchema : schéma du résultat structuré
  • annotations : indications sur le comportement du tool
Tool

TicketTools : dépendances et liste

<?php

namespace App\Mcp;

use App\Entity\Ticket;
use App\Repository\TicketRepository;
use Doctrine\ORM\EntityManagerInterface;
use Mcp\Capability\Attribute\McpTool;
use Mcp\Capability\Attribute\Schema;
use Mcp\Exception\ToolCallException;
use Mcp\Schema\ToolAnnotations;
use Symfony\Component\Serializer\Normalizer\NormalizerInterface;

final class TicketTools
{
    public function __construct(
        private readonly TicketRepository $tickets,
        private readonly EntityManagerInterface $em,
        private readonly NormalizerInterface $normalizer,
    ) {
    }

    /**
     * Liste les tickets de support, éventuellement filtrés par statut.
     */
    #[McpTool(name: 'list_tickets', annotations: new ToolAnnotations(readOnlyHint: true))]
    public function list(#[Schema(enum: ['open', 'closed'])] ?string $status = null): array
    {
        $tickets = $status ? $this->tickets->findBy(['status' => $status]) : $this->tickets->findAll();

        return ['tickets' => $this->normalizer->normalize($tickets)];
    }

Le conteneur de Symfony injecte le dépôt, l'EntityManagerInterface, qui servira aux tools d'écriture, et le NormalizerInterface, qui transforme les tickets en tableaux.

SDK : Schema generation

La description compte

Le modèle choisit ses tools uniquement à partir de leur nom, de leur description et de leur schéma.

À éviter

  • process : « Traite les données »
  • Paramètre $s sans description
  • Un tool géant avec un argument action

À privilégier

  • Un verbe et un objet : close_ticket
  • Ce que fait le tool, ce qu'il renvoie et quand l'utiliser
  • Un tool par action, des paramètres typés et contraints

Une description ambiguë produit des appels erronés, quel que soit le modèle.

Le résultat d'un tool

  • content : contenus pour le modèle (text, image, audio, resource_link…)
  • structuredContent : valeur JSON conforme à l'outputSchema
  • isError : true si le tool a échoué

Déclarer le résultat : outputSchema

    /**
     * Récupère le détail d'un ticket à partir de son identifiant.
     */
    #[McpTool(
        name: 'get_ticket',
        annotations: new ToolAnnotations(readOnlyHint: true),
        outputSchema: [
            'type' => 'object',
            'properties' => [
                'id' => ['type' => 'integer'],
                'title' => ['type' => 'string'],
                'status' => ['type' => 'string', 'enum' => ['open', 'closed']],
            ],
            'required' => ['id', 'title', 'status'],
        ],
    )]
    public function get(int $id): array
    {
        return $this->normalizer->normalize($this->find($id));
    }

Le serveur doit renvoyer un structuredContent conforme au schéma déclaré. La méthode privée find() est présentée plus loin.

Output schema

Les annotations

AnnotationSignification
readOnlyHintLe tool ne modifie rien
destructiveHintLe tool peut supprimer ou écraser des données
idempotentHintRépéter l'appel avec les mêmes arguments n'a pas d'effet supplémentaire
openWorldHintLe tool interagit avec des entités extérieures (web, API tierces…)

Les hosts s'en servent par exemple pour demander confirmation avant un tool destructeur.

Ce sont des indications, pas des garanties : un client doit les considérer comme non fiables si le serveur n'est pas de confiance.

Tool annotations

Deux types d'erreurs

Erreur de protocole

Tool inconnu, requête mal formée, erreur serveur.

Réponse JSON-RPC error, peu exploitable par le modèle.

Dans le SDK : toute exception, avec un message générique.

Erreur d'exécution

Ticket introuvable, règle métier, API indisponible.

{
  "resultType": "complete",
  "content": [{ "type": "text", "text": "Le ticket #42 n'existe pas." }],
  "isError": true
}

Dans le SDK : ToolCallException.

Une erreur d'exécution explicite permet au modèle de se corriger et de réessayer.

Error handling

TicketTools : création et assignation

    /**
     * Crée un ticket de support.
     */
    #[McpTool(name: 'create_ticket')]
    public function create(#[Schema(minLength: 5)] string $title, string $description): array
    {
        $ticket = new Ticket()
            ->setTitle($title)
            ->setDescription($description)
            ->setStatus('open');
        $this->em->persist($ticket);
        $this->em->flush();

        return $this->normalizer->normalize($ticket);
    }

    /**
     * Assigne un ticket à un membre du support.
     */
    #[McpTool(name: 'assign_ticket', annotations: new ToolAnnotations(idempotentHint: true))]
    public function assign(int $id, string $assignee): string
    {
        $this->find($id)->setAssignee($assignee);
        $this->em->flush();

        return "Ticket #$id assigné à $assignee.";
    }

Un ticket chargé par Doctrine est suivi : modifier sa propriété puis appeler flush() suffit à l'enregistrer.

TicketTools : fermeture

    /**
     * Ferme un ticket résolu.
     */
    #[McpTool(name: 'close_ticket', annotations: new ToolAnnotations(destructiveHint: true))]
    public function close(int $id): string
    {
        $this->find($id)->setStatus('closed');
        $this->em->flush();

        return "Ticket #$id fermé.";
    }

    private function find(int $id): Ticket
    {
        return $this->tickets->find($id) ?? throw new ToolCallException("Le ticket #$id n'existe pas.");
    }
}
  • find() n'a pas d'attribut : ce n'est pas un tool, mais elle signale un ticket inexistant par une ToolCallException
  • Fermer un ticket est une action destructrice : nous ajouterons une confirmation de l'utilisateur au chapitre MRTR et elicitation

MCP configuration reference

Et l'état entre deux appels ?

MCP est sans état : un serveur ne peut pas s'appuyer sur la connexion pour relier deux appels. Il renvoie un identifiant explicite que le modèle transmet ensuite :

// → tools/call
{ "name": "create_basket", "arguments": {} }
// ← résultat
{ "structuredContent": { "basket_id": "bsk_a1b2c3" } }
// → tools/call
{ "name": "add_item", "arguments": { "basket_id": "bsk_a1b2c3", "sku": "…" } }
  • Des identifiants opaques et difficiles à deviner
  • Une durée de vie annoncée dans la description du tool
  • Une erreur d'exécution claire si l'identifiant a expiré
